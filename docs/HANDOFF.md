# 開発引き継ぎ — STARFALL / Sector 07

## 目的と方針

Godot 4 で作った、Mac へ移して開発を継続できる縦スクロール・シューティングの試作です。既存ゲームの複製ではなく、オリジナルの機体・敵・背景・音源を用いています。弾幕の密度を上げるより、読みやすい敵の動き、少数の狙い弾、短い再挑戦の流れを優先しています。

- 開発・検証対象: **Godot 4.6.3 Standard / GDScript**
- レンダラー: **GL Compatibility**
- 内部表示: **480 × 720**、初期ウィンドウ: **480 × 720**
- 更新: 60 Hz の `_physics_process()`
- 外部アドオン・`.NET`・ネットワーク・アカウント・鍵: 不要
- リポジトリ: <https://github.com/you-sk/godot-vertical-shooter>
- macOS / M1: ソースの引き継ぎ対象。実機確認とネイティブ書き出しは未実施

`project.godot` の互換性フィーチャー表記が古い 4.x を示していても、そのバージョンでの動作検証を意味しません。まず 4.6.3 で引き継ぐのが安全です。

## 最初の起動

1. Godot のプロジェクトマネージャーから `project.godot` をインポートします。
2. リソースインポート終了後に F5 で実行します。Mac では fn キーが必要な場合があります。
3. `scenes/main.tscn` を開いた状態なら F6 でも実行できます。
4. タイトルから Enter、移動は矢印 / WASD、射撃は Z / Space です。
5. Esc / P でポーズ。M でミュートを切り替えられます。

より詳しい操作・ルールは [README.md](../README.md) を参照してください。

## アーキテクチャ

| ファイル | 主な責務 |
|---|---|
| `scenes/main.tscn` | 起動ルート。ゲームオブジェクトはスクリプトから生成 |
| `scripts/main.gd` | 状態遷移、入力設定、シミュレーション順序、衝突判定、スコア、UI、保存 |
| `scripts/player.gd` | 自機移動・画面内制限、連射、武器レベル、低速移動、描画 |
| `scripts/enemy.gd` | 4 種類の通常敵、軌道・狙い弾・HP・得点・描画 |
| `scripts/boss.gd` | 登場、HP、予兆、3 種類の攻撃、後半の攻撃間隔、描画 |
| `scripts/stage_director.gd` | 時刻・ウェーブ番号に基づく決定的な出現スケジュール |
| `scripts/bullet.gd` | 自機弾 / 敵弾の移動・寿命・描画 |
| `scripts/pickup.gd` | 武器強化アイテムの移動・描画 |
| `scripts/effect.gd` | 一時的な爆発エフェクト |
| `scripts/background.gd` | スクロールする背景と装飾 |
| `scripts/audio_manager.gd` | BGM、効果音用のプレイヤープール、ミュート、ポーズ |
| `tests/test_runner.gd` | ヘッドレス環境でゲーム本体を実行する回帰テスト |
| `tools/generate_audio.py` | 標準ライブラリーだけによる音源の生成・検証 |

### 状態と更新順序

ゲーム状態は `TITLE / PLAYING / PAUSED / GAME_OVER / VICTORY` です。プレイ時だけ `step_simulation()` が進み、自機 → ディレクター → 敵 → ボス → 弾 → アイテム → エフェクト → 衝突 → 後処理の順に更新します。

アクターの多くは `tick(delta)` と `_draw()` に責務を分けています。通常の Godot `Area2D` による検出ではなく、`main.gd` 内の円同士の距離判定を使用しています。`alive` を落としてから後処理で配列とノードを整理するため、反復中の直接削除には注意してください。自機の当たり判定は半径 6 ピクセルで、見た目の機体より小さくなっています。

画面・UI は主に Godot のベクター描画とフォールバックフォントを使用し、外部画像やフォントに依存しません。全体の座標系は 480 × 720 を前提にしているため、縦横比を変える際はレイアウトと移動制限も見直します。

## 調整しやすい場所

### ステージとウェーブ

`stage_director.gd`:

- `STAGE_DURATION = 144.0`: ボス出現までの秒数。
- `pickup_times`: 武器強化の出現時刻。
- `next_wave`: 最初の出現とウェーブ間隔。
- `spawn_wave()`: 5 パターンを巡回。48 秒区切りで敵数・構成が変化。
- 終盤 9 秒は新規ウェーブを止め、ボスへ移行する余白を設けています。

`enemy.gd` の `configure()` で HP・速度・得点・半径を、`fire()` で弾速・角度を調整できます。自機との距離が近すぎる場合や、後ろ向きになる場合には射撃を控えます。

### 自機・スコア

`player.gd` の `SPEED`、`HIT_RADIUS`、連射間隔、`fire()` が主要な調整点です。斜め移動は正規化し、低速移動は通常速度の約 52% です。

`main.gd` で初期シールド 3、最大 5、15,000 点ごとの追加シールド、被弾後の無敵 2.8 秒、拾得時の 500 点、ボス撃破時の 10,000 点を管理しています。被弾時は武器レベルが 1 下がり、周囲の敵弾を消して自機を中央下へ戻します。

### ボス

`boss.gd` の `MAX_HP`、`fire_timer`、`fire()` を調整します。登場中は接触ダメージ・被弾を無効化し、到着後に戦闘を開始します。HP 半分以下で射撃間隔が短くなります。扇状弾・左右砲門の狙い弾・縦方向の弾列の 3 パターンを使用しています。

### 音

`audio_manager.gd` が 48 秒の `bgm.wav` を全区間ループします。効果音は 16 個の `AudioStreamPlayer` を再利用します。音量は BGM と各呼び出し側の dB 値で調整できます。生成方法・音源の由来は [assets/audio/README.md](../assets/audio/README.md) を参照してください。

音源を変更しない通常の開発では Python 実行は不要です。再生成する場合はプロジェクトルートで:

```sh
python3 tools/generate_audio.py
python3 tools/generate_audio.py --validate-only
```

## 保存と個人情報

ゲームオーバーまたはクリア時に、ベストスコアのみを **`user://scores.cfg`** へ保存します。これは Godot の OS ごとのアプリデータ領域です。プロジェクト内の絶対パスを必要とせず、保存データを Git に含めません。ネットワーク通信、クラウド同期、分析イベント、利用者のアカウントはありません。

## 検証コマンド

プロジェクトルートから実行します。`godot` は PATH 上の実行ファイル名を示します。

```sh
godot --version
godot --headless --path . --editor --quit
godot --headless --path . --script tests/test_runner.gd
godot --path .
python3 tools/generate_audio.py --validate-only
```

キャッシュを除いた ZIP や新規クローンでは、先にインポートコマンドを実行します。終了コードと標準出力・標準エラーを確認してください。本書は手順と設計の説明です。実施済みの検証結果は [VERIFICATION.md](VERIFICATION.md) に記録しています。

### Mac で追加確認してほしい項目

- 初回インポートと F5 / F6 起動、ウィンドウサイズ・文字・描画。
- キーボードの上下左右・斜め移動、押しっぱなし射撃、低速移動。
- タイトル → 開始 → ポーズ → 再開 → タイトル → 再開始。
- フォーカスを外したときの自動ポーズ。
- 被弾、残機減少、無敵、強化アイテム、ゲームオーバー、連続リトライ。
- 144 秒の道中からボスへの移行、ボス撃破、クリア後の再挑戦。
- 音量・48 秒ループの継ぎ目、ミュート、ポーズ中の音停止。
- 終了・再起動後のベストスコア保持。
- 使用する実物のゲームパッドで各割り当てを確認。

### 自動デモ / キャプチャ

`main.gd` には QA 向けの追加引数があります。

```sh
# 自動移動・連射・無敵のデモ（通常プレイや難易度評価ではない）
godot --path . -- --demo
```

`--capture=<出力 PNG>` と `--capture-after=<秒>` も受け取ります。画像取得には描画可能な環境が必要で、ヘッドレス起動だけでは視覚品質を確認できません。デモの結果を通常プレイの難易度・クリア率の証明として扱わないでください。

`tests/visual_capture.tscn` をエディターで開き F6 を押すと、タイトル・通常戦・ポーズ・ボス・クリア・ゲームオーバーの 6 画面を `artifacts/` に保存します。描画可能な環境が必要です。このシーンはテストモードを使用し、音声再生やスコア保存を行いません。
